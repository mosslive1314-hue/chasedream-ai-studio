## Bug Fix — Runtime Crashes After UI Redesign

### Bug 1 (Critical): NextStepBar React Hooks Violation
- **Root cause**: `useNarrativeStore` hook was called AFTER a conditional `return null`, violating React Rules of Hooks
- **Impact**: Pages that don't have a `nextStep` entry (e.g. `/story-overview`, `/assets`) would skip the hook call, causing React to throw a render error and crash the entire page
- **Fix**: Moved all `useNarrativeStore` hook calls BEFORE the conditional return. Used 8 separate selectors (one per possible checkKey) and then looked up the result from a dataMap object. This ensures hooks are always called in the same order regardless of route.

### Bug 2: ScreenHeader Used Non-existent CSS Variables
- **Root cause**: `ScreenHeader` referenced CSS variables like `--color-background-primary`, `--color-text-primary`, `--color-border-tertiary` which don't exist in the project's `globals.css`
- **Impact**: All colors fell back to generic defaults (#fff, #222, etc.), causing visual inconsistency and broken theming on dark-themed pages
- **Fix**: Added `theme` prop to `ScreenHeader` accepting the same theme object structure as page themes (`{card, s2, border, primary, text, text2, text3, error}`). Falls back to project-level CSS variables (`--surface`, `--border`, etc.) when no theme provided.

### Bug 3: Screens Not Passing Theme to Shared Components
- **Root cause**: `ScriptScreen`, `InteractionScreen`, `NodesScreen` used their own theme objects (SCRIPT_THEME, INTERACTION_THEME, NODES_THEME) but didn't pass them to `ScreenHeader` or `NextStepBar`
- **Fix**: Added `theme={S}` prop to both `ScreenHeader` and `NextStepBar` in all 4 screen components
