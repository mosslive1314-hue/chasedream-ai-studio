## BugFix: Maximum update depth exceeded 无限循环 (21:15)

### 根因
SimulatorScreen 的 `useEffect([storyNodes, nodeEdges, rebuildPlayableGraph])` + `rebuildPlayableGraph()` → `set({ playableGraph })` → Zustand set 导致 `rebuildPlayableGraph` 函数引用变化 → useEffect 重复触发 → 无限循环

### 修复
1. **use-narrative-store.ts** — `rebuildPlayableGraph` 加 JSON.stringify guard，graph 不变时跳过 set
2. **SimulatorScreen.tsx** — 用 useRef pattern 把 `rebuildPlayableGraph` 从 useEffect 依赖数组中移除
3. **SimulatorScreen.tsx** — 第二个 useEffect 加 `nodeId !== startNodeId` 额外 guard

### 经验
- Zustand store action 引用会在 set() 后变化，不应放入 useEffect 依赖数组
- store action 内部 set() 前应做内容比较，避免无意义的 set 触发级联渲染
- **CRITICAL**: Zustand selector 中禁止调用函数 `s => s.getHistory()` — 每次调用返回新引用，Zustand 用 Object.is 判定变化 → 无限循环。应改为 `s => s.history` + useMemo 派生

### BugFix 2: VersionScreen 无限循环 (21:27)
**症状**: 点击「版本管理」→ Maximum update depth exceeded
**根因**: `useVersionStore(s => s.getHistory())` 和 `useVersionStore(s => s.getActiveBranch())` 在 selector 中调用函数，每次返回新引用 → 无限循环
**修复**: 改为 `s => s.history` + `s => s.activeBranchId`，用 useMemo 派生计算
