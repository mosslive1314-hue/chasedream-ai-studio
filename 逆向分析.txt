# AltFlow 互动影视游戏开发平台 — 逆向分析报告

## 一、平台总览

AltFlow 是互影科技（AltStory）于2026年6月发布的AI互动叙事创作平台。平台定位为「垂类互动叙事创作AI Agent」，核心理念是 **「创作者为核心，AI做辅助」**——AI负责80%的重复性/通用性工作（文本拆解、基础分支搭建），创意构思、人物塑造等核心创作环节由人工完成。

平台隶属于上海互影数字科技有限公司（沪ICP备2026026969号-1），团队自2017年起深耕互动叙事赛道，是国内互动影视赛道的开创者与标准制定者，参与国家互动视频行业标准制定。已获经纬中国、真格基金、阅文集团、叠纸游戏等多轮融资。

### 2.2 逐个元素分析

| 元素 | 内容 | 设计意图 |
|------|------|----------|
| **Logo** | "AltFlow" 文字Logo（含图片标识） | 品牌识别，位于左上角标准位置 |
| **语言切换** | "中" 按钮 | 中英文双语支持，面向全球创作者 |
| **登录入口** | "登录" 按钮 / 已登录显示用户名 | 区分游客和已认证用户状态 |
| **主Slogan** | "Every Choice Creates A World" / "所有未发生，都值得被创造" | 中英双语品牌主张，直接传达互动叙事核心——「选择创造世界」 |
| **示例项目卡片** | 三张项目卡片：「一个邪恶中世纪的故事」「云端上的糖果小镇」「蒸汽纪元的天空之国」 | 展示平台产出物风格多样性，降低新用户创作焦虑，提供灵感参考 |
| **主CTA按钮** | 「改编剧本」「开始创作」 | 双入口设计——改编现有IP（面向IP方）和从零创作（面向独立创作者） |
| **剧本工作台** | 页面标签/工作区名称 | 核心功能入口，暗示这是创作的主阵地 |
| **安全验证** | 滑块拼图验证 | 反爬/反机器人机制，保护平台资源 |

### 2.3 视觉设计特征

从页面文本和元数据推断的设计风格：

- **极简主义设计**：首页仅展示品牌主张 + 示例项目 + 两个CTA按钮，没有冗余信息
- **暗色/深色主题倾向**：页面有深色背景元素（从"退出登录"的配色推断）
- **大留白 + 聚焦核心行动**：用户进入后一眼看到Slogan，然后被引导至两个核心CTA
- **卡片式设计**：示例项目以卡片形式呈现，每张卡片包含项目名和封面图
- **双语国际化**：默认中文但支持切换，Slogan为双语展示

## 三、核心产品模块架构

### 3.1 模块全景图

```
                    AltFlow 平台
                         │
        ┌────────────────┼────────────────┐
        │                │                │
   AI智能拆解      智能模型路由      ACE互动编辑器
   (64并发单元)    (Benchmark系统)   (一体化工作台)
        │                │                │
   ┌────┴────┐    ┌─────┴─────┐    ┌─────┴──────┐
   │         │    │           │    │            │
 文本解析  要素提取  剧本撰写  分支设计  可视化编排  媒资管理
 人物关系  剧情脉络  成片编辑  效果测评  多人协作  发布预览
 冲突节点  情绪曲线  盲测机制  动态路由  项目管理  组件系统
```

### 3.2 模块一：长篇内容智能拆解体系

**功能描述**：
- 搭载 **64个并发智能单元**，并行处理文本
- 可在 **125秒内完成50万字文本**的全维度拆解
- 自动提炼：人物关系图谱、剧情发展脉络、核心冲突节点、情绪曲线
- 输入格式：小说、剧本等长篇文本

**设计原因**：
互动叙事需要将线性文本转化为非线性分支结构，传统人工梳理一部50万字的小说需要数周甚至数月。该模块解决IP方海量存量内容人工梳理效率低、成本高的核心痛点，为大型IP转化为互动内容提供自动化基础设施。

**技术实现推断**：
- 采用并发分片策略，将长文本分割为多个片段并行处理
- 使用NLP模型进行实体识别、关系抽取、事件检测
- 输出结构化的JSON数据供编辑器消费

### 3.3 模块二：多模型智能路由与测评体系（Benchmark）

**功能描述**：
- 不依赖单一大模型，根据创作环节智能匹配最优模型
- 剧本撰写、分支设计、成片编辑等不同环节调用不同模型
- 配套常态化**盲测、反向标注、效果打分**机制
- **每周迭代评估**模型能力并动态调整分配策略

**设计原因**：
不同大模型在不同任务上的表现差异显著（如Claude擅长创意写作、GPT擅长逻辑推理）。单一模型无法在所有创作环节都保持最优表现。通过Benchmark系统，平台可以规避单一模型的能力短板，始终保持各环节的最优输出质量。

**技术实现推断**：
- 模型注册中心 + 任务调度器架构
- A/B盲测框架：同一任务分发给多个模型，人工评分后反馈
- 动态权重分配：基于评分数据调整模型选择策略

### 3.4 模块三：ACE互动内容专属一体化编辑器

这是平台的核心用户界面，来自 altstory.com 的产品功能介绍文档。包含六大子模块：

#### 3.4.1 可视化编辑（流程图式剧情编排）

**功能**：
- 用户可将视频节点拖拽至流程图中
- 通过节点间连线直观展示视频之间的跳转逻辑
- 系统实时检测数据并保存，对配置错误位置进行提示
- 支持**章节拆分**，提高流程图可阅读性

**UI设计推断**：
- 类似节点编辑器（Node Editor），如Unreal Engine Blueprint或ComfyUI的节点图界面
- 左侧或顶部为节点库面板
- 中央画布为核心编辑区，可缩放/平移
- 节点之间以带箭头的贝塞尔曲线或直角连线连接
- 连线标注跳转条件（如"用户选择A→节点3"）

**设计原因**：
互动叙事的核心特征是**非线性、多分支、条件跳转**。传统线性时间轴无法表达分支逻辑，流程图/节点图是最自然的可视化方式，降低创作者的认知负担。

#### 3.4.2 定制化组件系统

**功能**：
- 互动视频中所有可互动功能均通过**组件**实现
- 开发者实现复杂的定制化组件并与平台绑定
- 创作者在流程图中直接使用，实现组件的**多次复用**

**设计原因**：
互动内容需要各种交互形态（QTE、选择弹窗、解谜交互、道具收集等），如果每个项目都从零开发这些交互逻辑，成本极高。组件化架构将交互能力标准化、可复用化，让非技术创作者也能使用复杂交互。

**典型组件推断**：
- 选项选择组件（A/B/C分支）
- QTE快速反应组件（限时点击）
- 解谜组件（拖拽、组合、密码输入）
- 好感度/数值系统组件
- 对话选项组件
- 倒计时决策组件

#### 3.4.3 多人协作

**功能**：
- 互动视频创作涉及多个角色及团队参与
- 编辑器支持**实时同步更新**编辑数据
- 配置信息始终保持最新状态
- 所有协作人能第一时间看到编辑器变化

**设计原因**：
互动叙事创作天然需要多角色协作——编剧写剧情、设计师配置分支逻辑、美术准备素材、程序开发组件。类似Figma的实时协作能力是团队效率的基础设施。

#### 3.4.4 媒资管理

**功能**：
- 对视频、图片、音频等不同类型文件统一管理
- 支持预览、更新、下载项目资源
- 连接**云存储和私有文件存储系统**
- 实现素材的一键上传与替换

**设计原因**：
互动内容素材量极大（中长篇可达400-600分钟素材），需要一个集中的资产管理界面来避免素材混乱。

#### 3.4.5 一键发布预览

**功能**：
- 项目在编辑器内一键发布
- 自动对互动内容及媒资进行**转码、封装、优化**
- 生成互动视频专用格式（IVF™）
- 发布后点击链接即可快速预览
- 通过配置项、日志信息调试互动视频

**设计原因**：
传统互动内容制作需要手动打包、配置播放环境、调试兼容性。一键发布将这个过程自动化，让创作者专注于内容而非技术部署。IVF™是互影自研的互动视频封装格式，内置互动资源和逻辑，兼容HLS流媒体协议。

#### 3.4.6 项目管理

**功能**：
- 灵活管理项目权限
- 添加项目成员、配置角色
- 对项目文件资源库、开发信息等**细粒度权限**管理

**设计原因**：
企业级/团队级使用场景需要权限管控，不同角色（编剧、设计、审核）应有不同的访问和操作权限。

## 六、用户体验设计亮点分析

### 6.1 首页设计

- **双CTA策略**：「改编剧本」和「开始创作」分别对应两类核心用户——IP方（有内容但需要改编）和独立创作者（从零开始）。这是一种精准的用户分流设计。
- **社会证明**：直接展示三个不同类型的示例项目（中世纪奇幻、童话甜点、蒸汽朋克），让用户3秒内理解平台能产出什么。
- **品牌叙事**："Every Choice Creates A World"——Slogan本身就是互动叙事的定义，直接击中使用者的核心理念。

### 6.2 编辑器设计

- **所见即所得**：流程图式的剧情编排，创作者可以像画图一样构建复杂的互动剧情结构。相比传统用表格或代码管理分支逻辑，效率呈数量级提升。
- **实时反馈**：系统实时检测配置错误并提示，避免导出后才发现问题。
- **章节拆分**：长篇互动内容可达数百个节点，章节拆分功能保持了大型项目的可管理性。

### 6.3 AI集成体验

- **非侵入式**：AI在后台完成80%的脏活累活（文本拆解、分支框架搭建），创作者在前台做决策和创意，符合"AI辅助而非替代"的产品哲学。
- **智能路由透明化**：用户不需要关心底层用了哪个模型，平台自动匹配最优解。
- **成本可感知**：AI将十万字级别互动剧本基础框架成本从数万元压缩至数千元，创作周期从数月缩短至数周——这是对用户最直观的价值传达。

### 6.4 安全与验证

- 滑块拼图验证（反爬虫机制）
- 登录态管理（用户5849/退出登录）
- 这表明平台使用**基于Token的会话认证**，前端可能是React/Vue SPA架构

## 七、技术栈推断

| 层面 | 推断技术 | 依据 |
|------|----------|------|
| 前端框架 | React / Vue 3 (SPA) | 单页应用、动态路由、"剧本工作台"标签页切换 |
| UI组件库 | 自研/定制组件 | 暗色主题、节点编辑器等专业工具通常定制 |
| 流程图/节点编辑器 | 自研Canvas/SVG方案 或 React Flow / Vue Flow | 可视化剧情分支编排 |
| 后端 | Node.js / Go / Python | 高并发（64并发单元）、WebSocket实时协作 |
| 数据库 | PostgreSQL + Redis | 结构化项目数据 + 实时协作缓存 |
| 文件存储 | 云存储（OSS/S3兼容）+ 私有存储 | 媒资管理模块描述 |
| AI模型层 | 多模型路由（GPT-4/Claude/国产大模型） | Benchmark系统描述 |
| 视频处理 | 自研IVF™格式 + FFmpeg转码管线 | 一键发布转码功能 |
| 实时协作 | WebSocket / CRDT | 多人协作实时同步 |
| 认证 | JWT Token + 滑块验证码 | 登录态和反爬机制 |

## 九、关键设计原则总结

| 设计原则 | 在AltFlow中的体现 |
|----------|-------------------|
| **降低认知负担** | 流程图替代代码/表格管理分支逻辑 |
| **渐进式暴露** | 首页极简→工作台→编辑器逐层深入 |
| **AI辅助非替代** | AI负责80%重复工作，创意由人主导 |
| **组件化复用** | 交互组件一次开发、多项目复用 |
| **实时协作** | 类似Figma的多人同步编辑 |
| **一站式闭环** | 从AI拆解→编辑→发布→分发，全链路覆盖 |
| **移动端适配考量** | 多终端分发能力暗示响应式设计 |
| **安全与权限** | 滑块验证+细粒度角色权限 |
