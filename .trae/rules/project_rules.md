# 项目规则

## UI 设计原则（必须遵守）

### 核心原则：极简 + AI 原生

1. **最少按钮，最多功能** — 能通过自然语言对话完成的事，绝不加按钮。界面上的按钮越少越好。
2. **不要信息过载** — 同一区域不要堆砌大量按钮/文字/信息。用户上来不应该"一脸懵"。
3. **不要小字** — 禁止使用 10px 以下的文字。状态信息要么 readable 要么不显示。设计师自己都看不懂的信息不要给用户看。
4. **不要折叠面板遮挡内容** — 展开/收起的浮动面板如果会遮挡其他内容，就是坏设计。功能要有，但放在不遮挡的位置。
5. **不要多余的提示/快捷按钮** — 如果功能可以通过对话完成，不要在对话区上方放快捷按钮（如"创建场景""添加选择""检查一致性""路径测试"）。
6. **导入入口应在输入框** — 导入功能应以"+"按钮形式放在对话输入框内，不是工具栏独立按钮。
7. **不要冗余的工作流指示** — 工作流阶段引导不要单独占一行。如果需要，以更轻量的形式融入其他区域。
8. **不要手动 Expert 选择器** — 如果有管线驱动编排，就不需要用户手动选 Expert。编排状态以轻量方式呈现，不占独立行。

### 布局原则

- 对话区是核心交互入口，保持干净
- 画布区是预览/编辑区，不被浮动面板遮挡
- 属性编辑通过内联或模态框完成，不用遮挡式浮动面板
- 状态栏信息要 readable 或不显示
- 项目名/保存状态等信息放顶部工具栏，不要浮在画布上遮挡内容

## 功能实现铁律（必须遵守）

1. **禁止 mock/硬编码数据** — 所有功能必须写真实可运行的代码，数据在 Zustand store 中持久化，功能间能流转交换。不允许用 `mock`、`fake`、`dummy`、硬编码数组假装数据。
2. **禁止"UI 占位"** — 不允许只画 UI 不接逻辑。每个按钮、输入框、面板都必须有真实行为。
3. **AI 调用必须真实** — 演示模式（无 API Key）下，工具调用（一致性检查、路径测试等）仍走真实逻辑；只有纯文本生成可降级，且必须明确标注"演示响应"。
4. **数据流转必须真实** — 一个功能产生的数据（如角色、场景、镜头）必须能被其他功能读取和使用，不允许各功能用各自的孤立假数据。
5. **旧 16 页的专业设计思想必须融合** — 旧 Screen（ParseScreen 10 步管线、InteractionScreen 互动设计、CinematicEditorScreen 镜头编辑等）的设计思想要融入新 Studio 的管线阶段和画布视图，不是照搬 UI，而是把工作流逻辑接入。
